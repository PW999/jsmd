# Contributing

Thank you for considering contributing to this project. Bug fixes and new features are both welcome.

## Bug fixes

Bug fixes can be submitted directly as pull requests. Please include:

- A clear description of the bug and how to reproduce it.
- A regression test that fails before the fix and passes after.
- Only the changes necessary for the fix.

If the bug is not yet documented, open an issue first so it can be tracked.

## New features

Before implementing a new feature, open a discussion (or a feature request issue) describing the problem, the proposed solution, and possible alternatives. Features must fit the scope of the application. Proposals that are out of scope will be rejected, so discussing first prevents wasted effort on implementations that cannot be merged.

Once a maintainer agrees the feature is in scope, submit a pull request referencing the discussion.

## Pull requests

1. Fork the repository and create a branch from the main branch.
2. Keep pull requests focused; unrelated changes should go in separate PRs.
3. Ensure the test suite passes and add tests for new behavior.
4. Follow the existing code style.
5. Write clear commit messages and a descriptive PR summary.

## Code of conduct

Be respectful and constructive in all interactions. Maintainers may decline contributions that do not fit the project's direction.
